## 3. 定量结果

### 3.1 CSV 与 ULog 对齐验证

使用五路电机输出搜索时间偏移，得到：

```text
ULog time = controller CSV time + 5.93 s
```

将 PX4 的 NED/FRD 姿态转换为控制器使用的 ENU 显示约定后，两套日志的姿态
RMSE 为 Roll `0.044 deg`、Pitch `0.048 deg`、Yaw `0.082 deg`。ULog 中 Pitch
约为 `+11 deg`，控制器 CSV 中约为 `-11 deg`，只是坐标显示符号相反，并非两套
估计结果矛盾。电机/舵机 ULog 与 CSV 回读差异 P95 为 `0.0021/0.0025`。

ULog 没有 dropouts；空中期间位置、速度、高度、航向和姿态 reset counter 均未
变化，`dead_reckoning=0`，主 EKF 的 fault/health/timeout flags 均为零。估计器
没有证据可以解释持续的 `4 deg/12 deg` Roll/Pitch 偏差。

### 3.2 姿态与控制器状态

按相对高度大于 `0.3 m` 判定空中段，空中时间约为 `5.97--171.10 s`。去掉空中

| Roll | -4.22 deg | 1.70 deg | -7.54-- -1.66 deg |
| Pitch | -12.19 deg | 2.27 deg | -16.02-- -8.57 deg |
| SO(3) 姿态误差角 | 14.24 deg | 2.13 deg | 10.93--17.77 deg |
| Roll 控制力矩 | +0.111 N m | 0.090 N m | -0.037--+0.261 N m |
| Pitch 控制力矩 | -0.388 N m | 0.094 N m | -0.545-- -0.232 N m |
| Yaw 控制力矩 | +0.357 N m | 0.171 N m | +0.088--+0.625 N m |

在约 100 秒的遥控器 XY 基本回中悬停样本中，Roll/Pitch 均值仍为

三个控制力矩都没有到达配置限幅。电机命令约 `0.52/0.53/0.30`，舵机命令也

因此当前主要问题不是 DDS 丢指令、PX4 没执行或归一化命令打满。

## 4. 原因判断

### 4.1 姿态稳态误差没有被积分消除

本次 `direct_attitude_Ki=[0,0,0]`。机体需要保持约
`[+0.111,-0.388,+0.357] N m` 的持续修正力矩时，只能依靠非零姿态误差产生
比例项，所以会稳定在偏斜姿态，而不是回到目标零姿态。

代码即使在 `Ki=0` 时仍累积积分状态。稳态空中段内，Roll/Pitch/Yaw 积分状态
分别有 `99.54%/100%/99.87%` 的样本位于限幅。在线直接把 Ki 改成非零会把
已有饱和值瞬间乘入力矩，形成力矩阶跃。应先修改为：Ki 为零时不积分；Ki 从零
变为非零时清零或做无扰切换；执行器饱和时加入 anti-windup。

### 4.2 Pitch bias 的模型符号不能直接指导实机调参

当前尾电机力矩尺度为 `50 N * 0.664 m = 33.2 N m`，所以控制器内部
`HNTR_PITCH_BIAS=0.09` 对应约 `2.988 N m` 的模型力矩。稳态时姿态控制器平均
请求 `-0.388 N m` 修正。只按内部符号曾得到以下反推：

```text
0.09 - 0.388 / 33.2 = 0.0783
```

但实机观察明确表明参数越小尾部越低，与上述模型反推方向相反。因此 `0.0783`
不能作为物理调参建议，反而说明外部分配器中的 Pitch 力矩符号、尾部正方向或
推力模型至少有一项不能直接对应肉眼观察。下一次测试以实机方向为准，从 `0.09`
小步增加到 `0.10`，并同时记录机体 Pitch 和尾部高度变化；不要在空中在线修改。

### 4.3 “软”由主动限速和偏低姿态增益共同造成

- 本次姿态 `KR=[1.8,1.8,3.8]`，明显低于仓库原调参文件的
  `[4,5,14]`；力矩限幅从 `[2.5,3,8]` 降到 `[0.9,0.9,1.8]`。
- 但本次力矩没有碰到限幅，因此单独增大 `tau_limit` 不会改善手感。
- RC 经过 `0.35 s` 低通，机体 Y 方向加速度又限制为 `0.55 m/s^2`，左右移动
  天生比前后移动更柔和。
- 水平位置目标与实际位置的稳态偏差约为 X `-0.418 m`、Y `-0.167 m`；X 误差
  已接近 `0.6 m` 的目标领先限幅。XY 位置积分为零，持续水平补偿力同样需要靠
  位置误差维持。

### 4.4 舵机静态映射仍有模型不一致风险

包内辨识 YAML 给出明显非对称的实际角度/命令角度增益：一级正负方向约
`1.438/2.037`，二级约 `0.671/0.861`，而飞行控制器仍使用对称线性角度映射。
这些辨识值可能受旧 PWM 标定和测量定义影响，不能直接写进飞控，但说明分配器
认为的推力方向可能与真实方向不同。缺少本次舵机实测角度，无法从当前 CSV 将
该误差和重心/安装误差分离。

ULog 已确认归一化命令到最终 PWM 的数字链路正确，但这不等于 PWM 到真实关节
角度也正确。后续仍需用动捕或关节传感器复核实际角度。

另一个配置隐患是源码的 Y 方向默认值为 `+1`，飞行靠 JSON 覆盖成 `-1` 才正常。
应把正确实机符号固化到实机配置，并在缺少配置时拒绝启动，避免遗漏 JSON 后
方向反转。

## 5. 建议的调试顺序

1. 先修复 Ki 为零仍积分，以及在线启用 Ki 的无扰切换问题。
2. 按实机观察将 `HNTR_PITCH_BIAS` 从 `0.09` 小步增至 `0.10`；不要在空中在线
   修改，并通过短悬停确认尾部高度和 Pitch 误差方向。
3. 使用带无扰切换和 anti-windup 的新积分实现，从
   `Ki=[0.15,0.18,0.50]` 开始，检查积分状态、姿态均值和力矩是否收敛。
4. Roll/Pitch KR 小步提高到 `[2.1,2.1]`，D 提高到 `[1.4,1.4]`，保持当前
   `tau_limit`。实飞日志控制律回放中三个轴均未触发力矩限幅。
5. RC 滤波从 `0.35 s` 降到 `0.25 s`，机体 Y 加速度从 `0.55` 提到
   `0.70 m/s^2`；姿态悬停确认后再验证左右移动。
6. 下一轮继续同时保存控制器 CSV 和 PX4 ULog；若条件允许，记录两级舵机实际
   角度，重新核对 PWM、减速比、正负方向增益以及左右执行器同步性。

## 6. 结论

这次飞行总体可控，没有看到电机/舵机命令饱和或 PX4 执行器回读异常。“软”主要
来自保守姿态增益和 RC 滤波/加速度限制；持续姿态偏差则主要符合“固定物理偏差
+ Ki 为零”的特征。优先按实机方向校准 Pitch bias 并修复积分启用逻辑，比直接
大幅增加 P、D 或力矩限幅更有针对性。

ULog 对上述结论形成了独立验证，同时排除了本次飞行中的执行器 PWM 饱和、严重
电池压降、EKF reset/fault 和最新 `3131ddd4` 舵机标定映射不匹配。基于控制器
符号得到的 Pitch bias `0.0783` 与实机方向冲突，已废弃为调参建议。
